# Patches and upstream notes

Every change this image makes to the upstream CosmosEx code and release files, and upstream issues found along the way. Use it to decide what to send back to Jookie (ce-atari author).

- **Upstream:** worth sending to ce-atari / ce-atari-releases as-is.
- **Image-only:** only makes sense for this Buildroot image.
- **32/64:** whether the change is correct on both a 32-bit (armhf, e.g. stock Raspbian) and a 64-bit (aarch64) build.

Patch files are in `package/<name>/`, applied in order by Buildroot. They're made with `git format-patch` against the pinned commits, so `git am` applies them to the upstream repos directly.

## Build changes (not patches)

How `package/ce-atari/ce-atari.mk` builds upstream code; relevant if upstream wants cross-compile or 64-bit support:

- **ARMv6 flags:** `ce_main_app/makefile` hardcodes `CPU_FLAGS = -march=armv6 -mtune=arm1176jzf-s -mfpu=vfp -mfloat-abi=hard -marm`. We override `CPU_FLAGS` on the make command line. Upstream could make it `CPU_FLAGS ?=`.
- **Distro detection:** the makefile runs `./whichdistro.sh` on the build host to pick yocto/jessie/stretch. We pass `DISTRO=stretch`.
- **Prebuilt 32-bit civetweb:** `lib/libcivetweb_raspbian_*.a` are armhf binaries. We build civetweb from the bundled `lib/civetweb-master.zip` (the makefile already has such a rule, but only for `ONPC=yes`).
- **bcm2835:** built from the bundled `lib/bcm2835-1.55.tar.gz`. Its peripheral-base detection (`/proc/device-tree/soc/ranges`) works unchanged on a 64-bit kernel.
- **flash_stm32 / flash_xilinx:** their makefiles hardcode `gcc`; we compile them directly with the cross compiler.
- **App version:** the app reports its compile date (`__DATE__` in `version.cpp`) as its version, so every rebuild gets a new "version". We build with `SOURCE_DATE_EPOCH` set to the source commit's time, so it reports `2019-08-15`. Upstream could derive the version from the git commit instead.
